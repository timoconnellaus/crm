Microsoft 365 over Entra ID OAuth and Microsoft Graph, with three resources: SharePoint and
OneDrive, Outlook mail (one mailbox, own or shared) and Outlook Calendar. New Outlook mail can push
through a hook (`OutlookHookDriver`). It does not authenticate users (`providesAuth` is off).

## What we take

`src/**` (except `src/generated/`), `__tests__/**`, `README.md`, `AGENTS.md` and
`storage-schema.md`, copied by `scripts/vendor-gatekeepers.mjs`. These are upstream-owned: don't
edit them by hand. The `*types.txt -> *types.d.ts` symlinks (the agent-facing API served by
`getTypeScriptTypes()`) are kept as symlinks.

## Local modifications

- **Scope rename.** `@gadgets/*` imports point at `@crm/gatekeeper-interface`,
  `@crm/gatekeeper-kit`, `@crm/gatekeeper-observability` and `@crm/gatekeeper-configurator-ui`.
  The 35 source files this touched start with a
  `// Vendored from cloudflare/cloudflare-os@… Modified locally` comment.
- **Worker config.** Upstream generates `wrangler.jsonc` from `cloudflare.config.ts`. We removed
  `cloudflare.config.ts` and keep `wrangler.jsonc` by hand with upstream's settings (compatibility
  date and flags, the `AI` binding, the capnweb-validate build, Text module rules, DO migration
  `v0`) plus: name `crm-gatekeeper-microsoft`, `workers_dev: false`, `preview_urls: false`, and a
  comment listing the secrets and optional settings. No account IDs.
- **Types.** `worker-configuration.d.ts` is regenerated by `pnpm types`
  (`scripts/gatekeeper-worker-types.mjs`).
- **Replaced (ours):** `package.json` (scope, exact versions, Turborepo scripts, `vite` pinned to
  `7.3.6` for the decorator reason given in `../gatekeeper-mcp/UPSTREAM.md`; no `playwright`) and
  `tsconfig.json`. Like upstream's, the tsconfig checks the source and the tests as one program.
  It lists Node's types explicitly: upstream gets them transitively through the Playwright import
  in `__tests__/frame-host.ts`, and the configurator modules need them for `clearTimeout`'s
  signature. It leaves out the files we don't run (below).
- **Test configs.** `vitest.config.ts` (Node) is upstream's except that it excludes the three
  `__tests__/*-configurator-frame.test.ts` suites. `vitest.worker.config.ts` takes `assert-workerd`
  from `@crm/gatekeeper-interface` instead of `../../scripts/assert-workerd.ts`.
- **Added** `test/vendor.test.ts` with `vitest.smoke.config.ts`: a workerd smoke test of the
  `GatekeeperVendor` entrypoint against the real `wrangler.jsonc`, with remote bindings off (the
  `AI` binding is remote-only) and `preserveSymlinks` so the `types.txt` links load as text.
- **Removed:** `vite.config.ts` (Vite+ tasks, including `build:configurator`), `deploy-inputs.json`
  (upstream's deploy-wizard metadata for the secrets, now summarised in `wrangler.jsonc`),
  `vitest.contract.config.ts` and `scripts/` (`contract-sign-in.ts` and `office-render.ts`,
  maintainer tools for the live suite and for rendering Office files).

## Tests not run

- `__tests__/{calendar,outlook,sharepoint}-configurator-frame.test.ts` and `__tests__/frame-host.ts`
  drive the configurator frames upstream builds with the configurator-ui runtime, in Chromium
  through Playwright. We ship placeholder frames (see Shims), so there is nothing for them to test.
  The configurator logic behind the frames (`*-configurator.test.ts`) does run.
- `__tests__/contract/*` is upstream's opt-in suite against a live Microsoft 365 tenant, which is
  never part of upstream's `test` either. Its config is not kept.
- `__tests__/*.live.test.ts` run but skip themselves unless `MICROSOFT_LIVE=1` and live
  credentials are present, as upstream.

Totals: Node 40 files (1148 tests, 12 skipped in 3 skipped files), workerd 2 files (62 tests),
smoke 3 tests.
