**Decision: the embedding seam now uses Stage 5's event queue (ADR 0154 amendment, written)**
- When `InvocationContext.embedViaEvents` is set (crm-app and crm-runner set it when they have a real Vectorize binding and a model that can embed), the pipeline writes **no** `core_embedding_queue` row.
  - crm-runner's queue handler calls `embedFromEvents` (`apps/runner/src/extensions/embeddings.ts`), which calls `embedRecordEvents` in core.
  - On a model or Vectorize failure it writes the records to `core_embedding_queue` for the cron.
- Without Vectorize (local dev, e2e, tests) the pipeline keeps the old in-batch queue path plus the post-commit drain. Each write is embedded exactly once.
- Erase and `sync.ingest` still queue their own records, because Stage 5 emits no event for them.
- The deploy script now adds the `vectorize` binding to crm-runner too; `docs/deploying.md` and `architecture.md` are updated.
- The import cycle is gone after the merge (`retention.ts` now imports `invoke` lazily).
